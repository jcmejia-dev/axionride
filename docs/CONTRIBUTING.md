# Contributing to AxionRide

## Overview

AxionRide is a long-term production project. Contributions should be intentional, documented, and small enough to review confidently.

## Expectations

- Preserve Expo Router unless a documented architecture decision says otherwise.
- Do not introduce dependencies without a clear need and review.
- Keep feature work isolated by domain.
- Update documentation when behavior, architecture, or workflows change.
- Avoid unrelated refactors in feature pull requests.

## Before Opening a Pull Request

- Confirm the change matches an issue or documented task.
- Run the relevant local checks.
- Review changed files for accidental formatting or generated noise.
- Update documentation when needed.
- Include screenshots for UI changes once UI work begins.

## Code Review Standards

Reviews should prioritize correctness, maintainability, accessibility, performance, and user trust. Feedback should be specific and tied to project goals.

## Documentation Standards

Documentation should explain decisions, constraints, and tradeoffs. Keep it current enough that a new engineer can understand why the project is shaped the way it is.
